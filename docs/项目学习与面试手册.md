# 项目学习与面试手册

不要从代码第一行背到最后一行。按“问题—方案—证据—边界”学习，能自己回答下面五组问题就算真正吃透。

## 第一层：一分钟主线

用户在多轮对话里不断补充或修改约束，Agent 既要记住当前状态，又要判断是否需要调用工具。项目把最近对话、上一轮状态和工具说明交给 Gemma 3-1B，通过 QLoRA 让它稳定输出状态和工具决策；然后由确定性代码做 Schema 校验、缺参追问和风险控制，最后只允许只读工具自动执行。

## 第二层：必须会解释的六个点

1. 为什么不能只输入当前一句话？——指代、修正和跨轮补参会丢失语义。
2. 为什么使用 QLoRA？——1B 模型可本地训练，4bit 降低显存，只训练少量 Adapter 参数。
3. 为什么只对答案算 loss？——目标是学习 JSON 协议，不要求模型复述 Prompt。
4. 为什么模型不能直接执行工具？——生成结果不可信，必须经过 Schema、白名单、必填参数和风险策略。
5. 为什么要有 `ask_user`？——参数不足时猜测会造成错误查询，副作用工具甚至可能带来真实损失。
6. 为什么既看 JGA 又看槽位 F1？——JGA 要求整条状态完全正确，严格但能反映多轮一致性；F1 能显示局部抽取能力。

## 第三层：最可能被追问的取舍

- **为什么不用更大的模型？** 本项目验证的是本地小模型经过任务适配后能否承担窄而稳定的工具决策模块，不是追求通用问答能力。
- **为什么不是完整 Agent？** 完整 Agent 已由第一项目证明；这里刻意隔离模型适配和执行边界，便于做 Base-vs-QLoRA 对照。
- **受控缺参样本算造假吗？** 不算，但必须透明。自然数据缺少这类反例，所以用各 split 内真实地点值做单槽位消融，并单独记录 provenance。
- **Prompt 能不能代替微调？** 要用 Base 指标回答。只有完成同集对照后，才能证明微调在格式、状态或决策上带来多少增益。
- **为何风险不让模型输出？** 风险属于系统权限，不属于语言理解结果；放进注册表才不可被模型随意改写。

## 第四层：代码阅读顺序

1. `src/gemma_eval/tool_use.py`：先懂 Schema、注册表、策略和执行。
2. `src/gemma_eval/tool_use_data.py`：再懂输入 Prompt 和指标。
3. `scripts/build_tool_use_dataset.py`：看标签如何从 CrossWOZ 来。
4. `scripts/train_tool_use_qlora.py`：看 4bit、LoRA、label mask。
5. `scripts/evaluate_tool_use.py`：看 Base/QLoRA 如何公平比较。
6. `scripts/run_tool_use_demo.py`：把模型输出接进策略与 SQLite。

## 第五层：完成训练后要记录

- 本机 GPU、显存、Python/PyTorch/Transformers/bitsandbytes 版本；
- epoch、学习率、最大长度、有效 batch size、随机种子；
- Base 和 QLoRA 的全部指标；
- 至少三个失败案例：状态错、工具错、参数错；
- 一个缺参被追问、一个只读工具执行、一个打车被人工确认拦截的演示。
