# 简历与面试表达

## 推荐项目名

**轻量级 Agent 工具学习与可靠性运行框架（Gemma 3-1B）**

这个标题先说明交付物，再补模型名。它比“Gemma 多轮工具调用”更像完整系统，也不会夸成生产平台。

## 简历版本

### 项目简介

面向任务型 Agent 构建小模型 Tool-Use 后训练与可靠性验证框架，覆盖多轮 Agent Trace 数据构造、4bit QLoRA、结构化决策协议、受控工具运行时及分场景 Eval Harness。

### 项目要点

- 基于 CrossWOZ 官方划分构建多轮 Agent Trace 数据管线，统一历史上下文、累计 `belief_state`、工具 JSON Schema、决策目标及样本 provenance，并设计显式标记的缺参消融与指代/修正/跨领域 challenge 切片。
- 在 6GB RTX 3060 Laptop 上对 Gemma 3-1B 进行 4bit NF4 QLoRA 后训练，仅更新约 1.29% 参数；在 440 条独立测试集上将严格 JSON 合法率由 0% 提升至 96.36%，状态 Slot F1 达 89.17%，决策准确率达 91.82%，工具选择准确率达 86.93%。
- 实现 Tool Registry、输出 Contract、Policy Engine 与可审计 Runtime，将模型提议与执行授权解耦；对未知工具、缺失参数进行拒绝/追问，只读工具可自动执行，副作用工具强制进入人工确认。
- 构建 Base-vs-QLoRA Eval Harness，覆盖 JSON/Schema、JGA、状态与参数 Slot F1、决策混淆矩阵、误调用率及多轮难例切片；通过错误分析定位长状态匹配、参数精确生成和结束语误调用三类主要瓶颈。

## 30 秒介绍

这个项目解决的是 Agent 里靠近模型的一层：通用小模型怎样学会稳定的工具调用，以及代码怎样约束它不能乱调用。我把 CrossWOZ 多轮对话转换成带状态、工具 Schema、目标决策和来源标记的 Agent Trace，用 4bit QLoRA 微调 Gemma 3-1B，再通过 Contract、Tool Registry 和 Policy Engine 校验输出。最终测试集上决策准确率 91.82%、工具选择 86.93%，同时我还单独评估了缺参追问、无需工具误调用和 challenge 难例，并保留了参数 Exact Match 较低这个真实短板。

## 3 分钟主线

1. **问题**：API 大模型通常能做 Function Calling，但小模型在多轮状态、格式遵循和何时不调用上不稳定；而模型输出不能直接获得执行权限。
2. **数据**：把 CrossWOZ 每个用户轮转换成 history、previous state、current user 和目标决策，并统一为 Agent Trace；对自然数据不足的缺参场景做 split 内单槽位消融并显式标记。
3. **训练**：Gemma 3-1B 以 4bit NF4 加载，使用 LoRA r16；只训练目标 JSON，保留 Base 作为同设置对照。
4. **运行时**：模型输出 belief state、call/ask/no-tool、工具与参数；代码做 Schema、白名单、必填参数和风险校验，副作用工具必须人工确认。
5. **评测**：不仅看工具准确率，还看 JSON、Schema、状态 JGA/F1、参数 exact/F1、误调用率，并对指代、修正、跨领域和长状态切片。
6. **结果与不足**：结构、状态、决策和工具选择提升明显；参数完全匹配和结束轮误调用仍是主要问题，下一步会考虑 schema-guided decoding 和更强 no-tool 数据。

## 面试中不要说

- 不说“企业级”“生产可用”“真实派车”；
- 不说“复现 BFCL”，只能说评测分层受 BFCL/When2Call 启发；
- 不把 89.17% Slot F1 说成状态完全正确率，JGA 是 46.59%；
- 不说支持多工具并行或完整规划，当前每轮选择一个工具；
- 不把受控消融说成 CrossWOZ 原生样本；
- 不把 LoRA 说成训练了 Gemma 全部参数。

## 最容易被追问的五个点

1. 为什么 Prompt token 不算 loss？
2. JGA 和 Slot F1 为什么差这么多？
3. 为什么风险不能让模型自己判断？
4. Base 的误调用率 0% 为什么不是更安全？
5. 参数 Exact Match 只有 31.82%，下一步怎么改？

这些问题都能从仓库代码和自动报告中找到证据，回答重点是“设计原因—实现位置—指标结果—真实边界”。
